# Screen4Stream

Демонстрация экрана по WebRTC, как в Discord: выбираете окно или монитор, а зрители
открывают ссылку в браузере на любом устройстве в локальной сети.

Интерфейс — веб-страница, поэтому приложением можно пользоваться и в окне (Tauri),
и в обычном браузере по адресу http://127.0.0.1:8080.

## Что нужно установить

- Rust (stable) и Node.js 20+
- GStreamer 1.26 для MSVC x86_64, **оба** установщика: runtime и development.
  Папка `bin` GStreamer должна быть в `PATH`.
- `pkg-config`. Путь к `.pc`-файлам GStreamer прописан в [.cargo/config.toml](.cargo/config.toml) —
  поправьте его, если GStreamer установлен не в `C:/Programs/gstreamer`.

Cargo читает `.cargo/config.toml` только из текущей папки, поэтому все команды
запускайте из корня проекта.

## Запуск

```sh
npm install          # один раз
npm run build        # собрать веб-интерфейс в web/dist

cargo run -p screen4stream                 # приложение с окном и иконкой в трее
cargo run -p s4s-server -- --open          # без окна: интерфейс откроется в браузере
```

Закрытие окна прячет приложение в трей, трансляция продолжается. Выйти — «Выход» в меню иконки.

При первом запуске Windows спросит разрешение для брандмауэра — разрешите доступ
в частных сетях, иначе зрители с других устройств не подключатся.

### Разработка интерфейса

```sh
cargo run -p s4s-server    # API и signaling
npm run dev                # http://localhost:5173 с горячей перезагрузкой
```

В debug-сборке сервер читает `web/dist` с диска, поэтому после `npm run build`
достаточно обновить страницу, пересобирать Rust не нужно.

### Проверить захват без интерфейса

```sh
cargo run -p s4s-core --example sources   # список окон и мониторов + миниатюра в target/
cargo test --workspace
```

## Как это устроено

```
┌──────────── процесс Screen4Stream ────────────┐
│  Окно Tauri ──► http://127.0.0.1:8080         │        ┌─ браузер зрителя ─┐
│                                                │        │  /watch           │
│  HTTP-сервер (axum, :8080)                     │◄───────┤  fetch /api/public│
│    веб-интерфейс, /api/*                       │        │                   │
│  Signaling (:8443, WebSocket)                  │◄───────┤  WebSocket        │
│                                                │        │                   │
│  GStreamer:                                    │        │                   │
│  d3d11screencapturesrc → d3d11convert          │        │                   │
│    → d3d11download → webrtcsink ═══════════════╪═══════►│  <video>          │
└────────────────────────────────────────────────┘ WebRTC └───────────────────┘
```

| Папка | Что внутри |
|---|---|
| [crates/core](crates/core) | Список окон и мониторов (WinAPI), миниатюры, GStreamer-пайплайн |
| [crates/server](crates/server) | HTTP API, раздача интерфейса, signaling-сервер; бинарник без окна |
| [src-tauri](src-tauri) | Окно приложения и иконка в трее |
| [web](web) | Интерфейс на Svelte 5: [host](web/src/host) — ведущий, [watch](web/src/watch) — зритель |

- `webrtcsink` сам выбирает кодировщик (NVENC, Media Foundation, x264, VP8) и подстраивает
  битрейт под сеть каждого зрителя.
- Зритель общается с signaling-сервером через [web/src/lib/signalling.js](web/src/lib/signalling.js) —
  там по шагам расписано, как устанавливается WebRTC-соединение.
- Управление (`/api/*`) доступно только с этого компьютера; из сети видны лишь страница
  зрителя и `/api/public/*`.

## Известные ограничения

- Окно захватывается через Windows Graphics Capture и отдаёт кадры, только когда
  перерисовывается. Некоторые программы (например, Windows Terminal) не рисуют себя,
  пока перекрыты другими окнами, — интерфейс в этом случае покажет предупреждение.
- Свёрнутое окно захватить нельзя.
- `webrtcsink` кодирует видео отдельно для каждого зрителя: на слабой видеокарте
  много зрителей одновременно — дорого.
- Установщик (`npm run tauri build`) пока не включает DLL GStreamer — на компьютере
  без установленного GStreamer приложение не запустится.
